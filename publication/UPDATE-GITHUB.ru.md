# Как обновить существующий GitHub-репозиторий

Текущая DLL проверена в двух ограниченных локальных сценариях; её хеш и пределы проверки приведены в VALIDATION.md. Не называйте эту альфу подтверждённым полным прохождением. Сохраните известную проблему четвёртого этажа с Sell Creep и не называйте сокетный тест проверкой Radmin.

Подготовленный проект предназначен для репозитория [vladnow/GungeonTogether-LAN](https://github.com/vladnow/GungeonTogether-LAN). Порядок ниже использует браузер; установка Git и ввод команд не требуются.

## 1. Подготовьте исходники

1. Для резервной копии нынешнего состояния откройте репозиторий, нажмите **Code → Download ZIP** и сохраните его отдельно.
2. Распакуйте новый `GungeonTogether_LAN-0.3.2-source.zip` в пустую папку.
3. Откройте распакованную папку. На её верхнем уровне должны лежать `README.md`, `README.ru.md`, `LICENSE`, `Build-LAN.ps1` и папки `GungeonTogether`, `tests`, `publication`, `validation`.
4. Для обновления кода используйте содержимое этой папки. Сам source.zip затем можно прикрепить к релизу, но загрузка одного ZIP в список файлов не обновляет находящиеся там исходники.

## 2. Загрузите изменения кода

1. Откройте вкладку **Code** в своём репозитории и корень основной ветки **main**. Если основная ветка называется иначе, используйте её.
2. Нажмите **Add file → Upload files**.
3. Перетащите файлы и папки **изнутри** распакованного проекта в область загрузки. Верхнюю папку архива не перетаскивайте: иначе получится лишний уровень вложенности.
4. Проверьте список: `README.md` должен находиться прямо в корне, а код — по путям `GungeonTogether/Lan/...`. Существующие файлы с тем же путём обновятся; новые добавятся. История прежних коммитов сохраняется.
5. В **Commit message** укажите `Prepare 0.3.2 LAN alpha`.
6. Для проверяемого обновления выберите **Create a new branch**, например `release-0.3.2`, и подтвердите загрузку. На следующем экране создайте pull request в основную ветку.
7. В **Files changed** убедитесь, что README описывает 0.3.2 и известную проблему четвёртого этажа, присутствуют текущие LAN-исходники и проверки отображения, подтверждений ввода, задержки и видимости спрайтов, а игровых DLL, сохранений и личных логов нет.
8. После проверки нажмите **Merge pull request → Confirm merge**. Если ветка защищена, выполните требуемые именно вашим репозиторием проверки. Создавать релиз следует из ветки, в которой изменения уже объединены.

Веб-загрузка добавляет и заменяет файлы, но не удаляет произвольные старые файлы. Не удаляйте весь репозиторий ради обновления. Если в нём ранее случайно размещались папки с личными сохранениями, игровыми библиотеками или ключами, их нужно разбирать отдельно: удаление файла обычным коммитом не стирает его из истории.

Интерфейс загрузки принимает также папки; справка GitHub описывает ограничения количества и размера файлов: [Adding a file to a repository](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

## 3. Создайте скачиваемый релиз

1. В репозитории откройте **Releases → Draft a new release**.
2. В **Choose a tag** создайте новый тег `v0.3.2-alpha`. В **Target** выберите обновлённую основную ветку.
3. Заголовок: `Gungeon Together LAN 0.3.2 alpha`.
4. В описание вставьте содержимое подготовленного `RELEASE-NOTES-0.3.2.md`. Сохраните указанные там ограничения и требование обновления обоих ПК.
5. В область вложений добавьте:
   - `GungeonTogether_LAN-0.3.2-Thunderstore.zip` — установка через менеджер;
   - `GungeonTogether_LAN-0.3.2-source.zip` — подготовленные исходники;
   - `GungeonTogether_LAN-0.3.2-SHA256SUMS.txt` — контрольные суммы.
6. Отметьте **This is a pre-release**: это альфа, а полноценный забег и два физических ПК через Radmin не проверены.
7. Сначала сохраните **Save draft**, проверьте название, описание и наличие всех вложений. Когда всё верно, нажмите **Publish release**.
8. Скачайте установочный архив уже с GitHub и сравните его контрольную сумму с подготовленным файлом. Убедитесь, что ссылка на русскую инструкцию открывается и показывает новые английские названия кнопок.

GitHub автоматически предлагает свои `Source code (zip)` и `Source code (tar.gz)` для тега. Они содержат состояние репозитория. Для установки игрокам нужны приложенные установочные архивы.

Официальная справка: [Managing releases](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository?tool=webui), [About releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

## 4. Что проверить после обновления

- В README указаны версия 0.3.2, реальные ограничения, лицензия и исходный автор **Copyright (c) 2025 lam**.
- В Releases доступны три вложения (Thunderstore ZIP, source ZIP и контрольные суммы), версия отмечена как предварительная.
- В корне кода нет лишней вложенной папки проекта.
- Локальная подготовка не является отправкой на GitHub: действия публикации выполняются отдельно владельцем репозитория.
